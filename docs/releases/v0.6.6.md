# Forge 0.6.6 — Vendor Grok Code engine and live streams

Forge 0.6.6 is the dogfood cut after 0.6.5: Code uses the vendor Grok agent when the CLI is present, live turns show thought, mid-turn words, tools, and a vouched answer, and fenced code honors Voidglass or light.

## Highlights

- **Vendor Code engine.** In Code, a resolvable `grok` CLI runs `grok agent stdio`. Chat stays mini-Grok. A missing CLI or a fail before the session is live falls back to grok-acp with honest chrome.
- **Live streams.** Thought, mid-turn words, one tool rail, and a vouched Answer are distinct Forge surfaces. Status bar and composer footer share one live phase.
- **Skills.** On vouched Grok Code, `/` opens a Skills palette from the vendor catalog. Choosing one arms `/name` for Send. Chat and Mini-Grok do not fake a catalog.
- **Child agents.** Vendor-spawned children show identity plus Running / Done / Failed. Chat and Mini-Grok do not invent a roster.
- **Browser.** Vendor fetch-class work elevates to a Browser list (URL/title when vouched). Not a second Chrome. Chat and Mini-Grok do not invent a browser.
- **Fenced code.** Chat and Code language-aware highlighting follows Voidglass or light. Unknown or oversized fences stay plain. No syntax-theme picker.
- **Unchanged.** Review / Trusted / Bypass stay Forge policy in the Action dock. Plan, File changes, Verify, and Git review stay. grok-acp is not a skills or browser engine.

## Upgrade

Close Forge before running the installer. Existing per-user conversations and settings are retained by the current-user upgrade path.
Review remains the default. Trusted is saved per workspace. Bypass never persists as an active session mode.
If Check for updates is wired to this release’s `latest.json`, a 0.6.5 install can pick up 0.6.6 from GitHub.
