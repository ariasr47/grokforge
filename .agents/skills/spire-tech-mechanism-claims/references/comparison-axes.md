# Comparison axes

When two technical shapes compete, score each on:

1. **Complexity** — parts, states, and failure modes introduced.
2. **Cost** — build and operate (including review load).
3. **Scalability** — behavior under the BRIEF's expected load, not fantasy load.
4. **Team familiarity** — can this team ship and debug it?

State the winning option and which axis was decisive. If axes conflict, prefer the BRIEF's binding
constraints and promoted invariants over elegance.
